Inline review

Keep or undo, right where Claude wrote it.

Each pending edit gets a ✨ gutter star at its start and a subtle green/red line tint — toned down so a heavily edited file doesn't drown in color. Above it sits an inline menu: ✨ #N · +A −R · view changes, then Keep, Undo, Chat, View diff. In VS Code, "view changes" opens an inline review bubble right at the edit — no tab — with the diff in git's own colors (green/red text over translucent line fills), Claude's reasoning, the +A −R counts, and Accept · Revert · Chat · Prev · Next on the bubble's toolbar; View diff opens the same edit as a full diff tab in its own tab, with Prev/Next cycling the file's edits in place. In PyCharm the lens opens the edit's unified diff. Nothing touches disk until you say so.

  • Keep marks an edit reviewed — no file change.
  • Undo rewrites just that change back out.
  • Additions highlight green; removed lines show as red ghost text where they were.
  • Kept edits grey out; reverted ones stay struck through.
  • File heatmap (📄) spotlights Claude's lines; revision nav (⌥⌘[ / ⌥⌘]) diffs against a file's earlier edits.
  • A File History view follows the open file; the Stats tab shows a live review scoreboard + progress bar.

Surgical undo

Undo the middle edit. Keep the rest.

Undo isn't a whole-file rewind. It's a position-anchored 3-way line merge: the edit is peeled out while later edits to other lines stay put. Anchoring on line position — not fuzzy text search — keeps it correct even when the same line appears twice. A genuine overlap raises a clear conflict and offers a per-file restore instead of guessing.

Three edits to one file → undo #2 only → #1 and #3 survive.

after undo #2

VS Code & PyCharm

Two editors. One observatory.

Edits and Diffs live in the activity bar, grouping changes folder → file → class. Observations, Timeline, and Stats sit side by side in the bottom panel — a live dashboard next to your terminal, with a status-bar microscope counting pending edits in realtime.

The VS Code extension and the PyCharm/JetBrains plugin are full peers — the same trees, inline menus, click-to-diff review, dashboards, and keyboard loop (⌥⌘N next · ⌥⌘Y keep · ⌥⌘U undo · ⌥⌘[/⌥⌘] revisions), all over one store. Keep an edit in PyCharm and it greys out in VS Code and the CLI the same instant. The JetBrains plugin uses platform-only APIs, so it runs in PyCharm CE/Pro, IntelliJ, WebStorm, GoLand — any JetBrains IDE, including on a Remote Development host.

The dashboards

A change feed and a flight recorder.

Observations pairs a zero-token session recap with Claude's per-edit reasoning and a cross-session memory of each file (accept/revert history, revert-risk flags). Timeline is the session as a feed — newest first, consecutive edits to a file coalesced into one ×N row. Stats is the long view: step-line trends of edits (pending / accepted / reverted) and tokens (total / input / output, log axis) over Today / 7 days / 30 days, with live usage bars — context fill plus your 5-hour and weekly plan windows.

Zero-token capture

Hooks do the watching, not the model.

Claude Code fires a hook before and after every edit. The observatory snapshots the file on each side and appends one record to an append-only log — never spending a token, never touching the model's context.

Same store, no GUI

A full review deck in the terminal.

Prefer the shell, or running Claude Code headless? Every action has a command. The active session is resolved from your working directory — no ids to memorize.

  • status — hook health, session, counts
  • list --pending — filter by state or file
  • undo 2 — surgical, with a --force restore
  • clean --resolved — clear what you've reviewed

Quickstart

One command to first light.

# one command — CLI + VS Code & JetBrains extensions from the latest release, hooks wired, health-checked
$ curl -fsSL https://raw.githubusercontent.com/cell-observatory/claude-observatory/main/scripts/bootstrap.sh | bash
 
# anytime
$ claude-observatory doctor # check hooks · PATH · session · usage
$ claude-observatory update # update to the latest release
!

Install the hooks with Claude Code closed. A running session snapshots your hooks at start and reconciles from that snapshot — so hooks added mid-session silently won't take effect. The installer prompts you to run init; do it from a plain terminal, then launch Claude Code. Verify anytime with claude-observatory doctor. To share with a team, init --project writes the hook into a checked-in ./.claude/settings.json.

Building from a clone instead? ./install.sh sets up the CLI + VS Code extension, and ./scripts/install-jetbrains.sh the JetBrains plugin. Re-run the one-liner (or claude-observatory update) to upgrade.
