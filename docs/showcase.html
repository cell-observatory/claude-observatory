Inline reviewPLATE I

Keep or undo, right where Claude wrote it.

Pending edits are marked in the gutter with a ✨ tag. Hover anywhere on the edited text for the card — Claude's reasoning for the change, plus Keep to accept, Undo to surgically revert, Diff to inspect, or Chat to ask about it. Identical in VS Code and PyCharm. Nothing touches disk until you say so.

  • Keep marks an edit reviewed — no file change.
  • Undo rewrites just that change back out.
  • Kept edits grey out; reverted ones stay struck through.

Surgical undoPLATE II

Undo the middle edit. Keep the rest.

Undo isn't a whole-file rewind. It's a position-anchored 3-way line merge: the edit is peeled out while later edits to other lines stay put. Anchoring on line position — not fuzzy text search — keeps it correct even when the same line appears twice. A genuine overlap raises a clear conflict and offers a per-file restore instead of guessing.

Three edits to one file → undo #2 only → #1 and #3 survive.

12BOT # edit #3
after undo #2

6L6 # #2 reverted
12BOT # kept ✓

VS Code & PyCharmPLATE IV

Two editors. One observatory.

The VS Code extension and the PyCharm/JetBrains plugin are full peers — the same trees, inline lenses, hover cards, dashboards, stats, and keyboard loop (⌥⌘N next · ⌥⌘Y keep · ⌥⌘U undo), all over the same store. Keep an edit in PyCharm and it greys out in VS Code and the CLI the same instant. The JetBrains plugin uses platform-only APIs, so it runs in PyCharm CE/Pro, IntelliJ, WebStorm, GoLand — any JetBrains IDE, including on a Remote Development host.

VS Code — the Edits tree, inline review with the hover card (Claude's reasoning + Keep/Undo/Diff/Chat), and the Observations · Timeline · Stats panel.

PyCharm — the same session, same store: Edits tool window, the lens + hover card, and the Claude Observatory Dashboards window.

The dashboardsPLATE V

A change feed and a flight recorder.

Timeline is the session as a feed: newest first, consecutive edits to the same file coalesced into one ×N row with the combined delta and Claude's own change summary. Stats is the long view — step-line trends of edits (pending / accepted / reverted) and tokens (total / input / output, log axis) over Today / 7 days / 30 days, with live usage bars below: context fill plus your 5-hour and weekly plan windows, reset countdowns and ~token estimates included.

  • Timeline rows expand to individual edits, statuses intact.
  • The stats scan runs in a subprocess with an incremental cache — the UI never blocks.
  • Usage values are stamped with their age when the status-line cache goes stale.

Zero-token capturePLATE VI

Hooks do the watching, not the model.

Claude Code fires a hook before and after every edit. The observatory snapshots the file on each side and appends one record to an append-only log — never spending a token, never touching the model's context.

QuickstartSETUP

Three commands to first light.

# from the repo
$ ./install.sh # deps → build → CLI → VS Code ext → status line
$ ./scripts/install-jetbrains.sh # the PyCharm/JetBrains plugin
 
# or by hand
$ npm install && npm run build
$ npm i -g ./packages/cli # `claude-observatory` command
$ claude-observatory init --with-statusline # hooks + usage bars (backs up settings)
!

Install the hooks with Claude Code closed. A running session snapshots your hooks at start and reconciles from that snapshot — so hooks added mid-session silently won't take effect. Run init from a plain terminal, then launch Claude Code. Verify anytime with claude-observatory status. To share with a team, init --project writes the hook into a checked-in ./.claude/settings.json.
