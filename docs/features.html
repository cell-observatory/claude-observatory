Every surface, in detail.

Seventeen ways Claude Observatory keeps you in the loop — inline, in the sidebar, in the terminal, and across both editors. Screenshots are from the bundled demo session.

01
Inline review

The change, right where it happened.

A gutter star marks each Claude edit; a clearly-visible whole-line highlight — green over added lines, red over removed, with a matching change-bar down the gutter — colors exactly what moved. Click view changes and the diff opens inline — in git's own colors, with Claude's reasoning and Keep / Undo / Chat / View diff on hand.

02
Per-edit diffs

Any edit, as its own before and after.

Open a single change as a dedicated diff tab and step through the file's edits with Prev / Next in the title bar — without losing your place.

03
Surgical undo & file history

Undo one edit. Keep the rest.

A position-anchored 3-way merge reverts a single change while later edits to the same file survive. File History lists just the active file's edits, newest first, and follows the editor as you switch tabs.

04
Timeline

The session as a change feed.

Files ordered by most-recent activity, each expanding to its edits. Adjacent edits to the same file coalesce into a single run, so a busy session stays legible.

05
Observations

What Claude was thinking.

A zero-token session recap on top, then each edit's real reasoning parsed from the transcript. Every row carries the observatory's memory of that file — its cross-session accept/revert history, so files that get reverted often are flagged.

06
Stats

Progress, tokens, and usage.

A top bar names the active Claude Code session and carries a Search-edits box that filters the edit list. Below it, a live review scoreboard — pending (click the count to jump to the oldest edit awaiting review), accepted, reverted — with a progress bar, a token step-line plot over Today / 7 days / 30 days, and context plus 5h / week plan-usage bars.

07
Heatmap

A spotlight on the edits.

Dim every unmodified line so Claude's changes stand out. One toggle turns a heavily-edited file into a focused view of exactly what moved.

08
Conflict resolution

It never guesses.

When an undo would overlap later changes, the observatory refuses rather than clobber — and offers an explicit --force restore. Anchored on line positions, not fuzzy text, so it stays safe against duplicated content.

09
The CLI backend

Review without leaving the shell.

The claude-observatory CLI is a first-class front-end over the same store — list, diff, keep, and surgically undo from your terminal. Its --json surface is what both editors build on.

10
Navigation bar

Drive the review from any surface.

One review bar on three surfaces — the status bar, the editor's title bar, and a single floating bubble over the live edit. Diff n/m steps the open file's pending edits while File n/m walks every file that has them, and the counters follow the active editor. It's two-tier — the File axis plus Clear, Spotlight, and Search show whenever anything's pending; the Diff axis and per-edit Keep / Undo / Accept File / Reject File appear only when the open file has edits — and the ⌥⌘ shortcuts still work.

11
Action timeline

Every tool call, not just the edits.

A zero-token, typed timeline mined from the transcript — every read, grep, shell command, web fetch, subagent spawn, and to-do update Claude made this session, each correlated with its result. The new Actions view — a panel beside Observations, Timeline, Change Map, and Stats in VS Code, a pane in the JetBrains Dashboards — groups them by category and stays curated by default, with a Show all toggle for reads, searches, and meta. Errors always surface; edit rows link straight to their review. From the shell: claude-observatory actions (alias trace) — a human feed or --json, filtered by --category, --errors, --limit, and --all.

12
Risk & egress

Two audits, zero tokens.

Both mined from the same action timeline, neither costs an extra Claude token. Risk flags the shell commands that can bite — data loss (rm -rf, git reset --hard, force push), remote code (curl | sh), privilege escalation (sudo), or credential-file access — as ⚠ high / med badges on those rows in Actions, plus claude-observatory risk. Egress answers “what did this session touch off-machine?” — WebFetch hosts, MCP servers, and network shell commands, each marked remote or unknown — pinned as an Egress node atop the Actions view and available as claude-observatory egress. Both are purely additive: no change to the store or its format.

13
Subagent tracking

Every subagent, its own timeline.

When Claude spawns a subagent (the Task / Agent tool), its work no longer vanishes into a side file. A Subagents node in the Actions view lists each one — expandable into its own reads, edits, and shell calls — with per-subagent metrics (duration, tokens, tool calls, status) mined zero-token from the subagent transcript and correlated to the spawn. From the shell: claude-observatory subagents (alias agents), a human feed or --json.

14
Fleet & cross-agent awareness

See what the other agents are doing.

A Fleet node lists the other Claude Code sessions working in the same project — active or idle (from transcript freshness), their pending edits, the files they've touched, and any risky commands they ran. Read-only and path-only: no file contents cross between agents. From the shell, claude-observatory siblings (alias fleet) is an agent-facing digest an agent can call mid-run to avoid stepping on a sibling's work.

15
Metrics

The session by the numbers.

One readout rolls up what the session cost and did — lines added and removed, tool-call and error counts, per-subagent duration and tokens, and tool latency (median / p95 / max, from each call's tool_use → tool_result gap). All derived, zero-token: claude-observatory metrics, human or --json.

16
Cross-editor parity

The same tool in both editors.

VS Code and JetBrains render the identical review surfaces over one backend — icon-only tabs, inline review, and the bottom dashboards alike. Decisions made in one show up in the other.

17
Change map

The session's changes at a glance.

A bird's-eye read of everything Claude touched, in one panel. Claude's own to-dos become chapters across the top — click one to brush the map down to just the files that goal produced. A one-row proportion strip shows where the work landed by module; click a segment to filter. Below, every file is ranked by churn with a bar, coloured by review status (worst-unreviewed-wins, so a module never reads reviewed while something under it is still pending). Hover a row for the class it touched and Claude's reasoning; click to open the real diff. Every rollup is computed once in core and rendered as-given by both editors — from the shell: claude-observatory changemap --json.
